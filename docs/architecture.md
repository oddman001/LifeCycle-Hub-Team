# 项目架构

## 团队本地运行链路

Windows 启动脚本调用 `start-team.mjs`。启动器先检测现有团队服务，再选择回环端口，运行构建并启动 `standalone.mjs`。浏览器访问 Node HTTP 服务，服务将请求交给 `worker.mjs` 生成的处理器。构建产物位于 `dist/server/index.js`。

`standalone-db.mjs` 将业务查询适配到 Node.js 24 的 `node:sqlite`。业务层继续使用现有预处理语句及事务接口。食品、药品分别管理档案和批次；衣物、电子设备和订阅沿用通用档案模型。CSS 和浏览器脚本通过构建随应用提供。

## 运行边界

团队本地版只监听 127.0.0.1，校验 Host 和写入来源。每个 Windows 用户拥有独立数据目录。离线版使用手动录入和文字规则提取。AI 识别是可选集成，作用范围仅限快速记录的文字输入：`standalone.mjs` 只把 `AI_*` / `OPENAI_*` 白名单变量注入处理器，配置后五个模块的文字描述先调用模型，调用失败或未配置时自动回退本地规则。照片与语音识别不属于文字识别范围，默认关闭，需显式设置 `AI_MEDIA=1` 才启用食品、药品的旧媒体入口。密钥只存在于本地进程环境，不写入数据库或页面。

代码保留历史演示站所需的 Worker 及会话路径。团队本地模式无需 Sites、D1 或第三方账户。团队仓库的提交和 CI 没有部署个人站或云端演示站的步骤。
