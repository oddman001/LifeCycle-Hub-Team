# 测试指南

## 自动化测试

```powershell
npm ci --ignore-scripts
npm run build
npm test
```

`npm test` 生成专用回归入口并运行 smoke、首页、筛选、设备、订阅、录入入口、日期、颜色和快速记录 AI 等测试文件。测试使用内存数据库和虚构数据，覆盖五模块 CRUD、食品日期与复合录入、药品计划和库存扣减、演示账号隔离，以及衣物 / 电子设备 / 订阅的 AI 识别与本地规则回退（使用模拟接口，不访问真实模型）。GitHub Actions 会在面向 `main` 的 PR 上运行这些检查。

## 功能回归

启动前把 `LIFECYCLE_TEAM_DATA_DIR` 指向一个新的临时目录。至少按改动范围执行以下测试，并在 PR 中描述结果。

| 变更范围 | 检查内容 |
|---|---|
| 食品 | 新建批次，编辑数量和位置，记录消耗。用「刚才买了两桶方便面，放在柜子里了」验证快速录入。 |
| 药品 | 创建档案和批次，记录一次实际服用，检查扣减与历史，并验证重复提交。 |
| 其余模块 | 从列表打开、新建、修改、删除组员自建的虚构档案。 |
| 快速记录 AI | 不配置密钥时确认提示「未配置 AI 识别」且结果标注「文字规则提取」；配置测试密钥后确认五个模块的文字输入标注「AI 识别」，断开网络或填错密钥时自动回退本地规则，且核对页保存前不写入数据库。照片/语音入口默认不出现，只有设置 `AI_MEDIA=1` 才显示。 |
| 启动与离线 | 双击启动、确认端口、断网运行、停止并重启，确认数据保留。 |
| 数据库 | 空库和旧库副本升级、重复启动、校验外键、恢复副本上读取关键记录。 |
| 演示认证 | 使用隔离环境的两个测试账号交叉读取、编辑和删除，并检查缺失配置时业务请求被拒绝。 |

已有自动化结果和人工实测分开记录。真实个人数据库不得作为测试目标。
